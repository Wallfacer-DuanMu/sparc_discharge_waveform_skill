## 新增搭建记录：Pipeline / Common / Input / Stage 3

以下内容为后续搭建过程中的新增说明，不替换上面的原始目录规划。

### 1. 三阶段 Pipeline 口径

当前工程已经形成了按阶段顺序串联的离线波形设计 pipeline：

```text
Stage 1 Breakdown
  → handoff_to_stage_2
Stage 2 Ramp-up
  → handoff_to_stage_3
Stage 3 Flat-top
  → final_state / 三阶段汇总材料
```

核心数据流是：

- Stage 1 生成击穿末态，包括初始 `Ip`、环电压、已消耗伏秒和线圈电流；
- Stage 2 接收 `handoff_from_stage_1`，完成升流和成形，并输出 `handoff_to_stage_3`；
- Stage 3 接收 `handoff_from_stage_2`，维持平台电流、位形、X 点和偏滤器打击点，并输出 `final_state`。

这个 pipeline 仍是学生作业级别的离线推演链路，不是实时控制系统，也不是完整自由边界平衡求解器。

### 2. Input / Output 约定

每个阶段都采用同类输入结构：

- `metadata`：案例信息；
- `handoff_from_stage_X`：上一阶段交接状态；
- `targets`：本阶段目标；
- `waveform_strategy`：波形生成策略；
- `engineering_limits`：工程约束；
- `physics_constraints`：物理约束；
- `control_constraints`：控制容差；
- `outputs`：期望输出通道；
- `validation`：检查开关。

每个阶段的输出重点包括：

- 逐时刻波形表；
- 阶段摘要；
- 末态线圈电流；
- 位形状态；
- 约束检查结果；
- 下一阶段交接字段或最终 `final_state`。

### 3. Stage 3 Flat-top 已完成内容

`stages/stage_3_flattop/` 已由占位文件扩展为完整工作包：

- `README.md`：补充了 Flat-top 阶段定位、输入字段、处理流程、输出结构、验证项和简化建模口径；
- `example.yaml`：给出结构完整的第三阶段输入示例，明确从 `handoff_from_stage_2` 继续；
- `models.py`：实现平台电流保持、低环电压维持、CS 慢速摆动、PF 小幅修正、Div 打击点扫描、VS 裕度、X 点/打击点与末态提取；
- `validation.py`：实现配置校验、Stage 2 交接检查、电流/环电压/伏秒/线圈/位形/X 点/打击点/VS/final_state 检查；
- `generate.py`：实现读取配置、调用模型、生成结果、输出 CSV/JSON/Markdown 报告的主流程。

已验证 `stage_3_flattop/generate.py` 可以基于 `example.yaml` 正常运行，并得到 `validation_passed=True` 的示例结果。

### 4. Common 目录当前状态

`common/utils.py` 和 `common/constraints.py` 目前仍是轻量占位文件，尚未被三个阶段主流程实际依赖。

保留它们的意义是：如果后续要统一三阶段代码中的配置读取、时间轴生成、平滑函数、CSV/JSON/Markdown 输出、电流限幅、变化率、伏秒等检查，可以逐步把重复逻辑抽取到 `common/`。

当前阶段为了避免过早抽象和增加学生作业复杂度，三个阶段仍优先采用“各阶段自包含”的实现方式。
