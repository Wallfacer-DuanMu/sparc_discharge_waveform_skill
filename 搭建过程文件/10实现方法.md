# Skill 实现方法说明

## 1. 先回答核心问题

`08工作流.md` 中第 65–68 行描述的是阶段一 Breakdown 的输出波形特征：

- `I_CS1/2/3(t)` 从预充磁电流开始快速摆动；
- `I_PF3/4(t)` 击穿前已到达零场预置值，击穿期间尽量平稳；
- `I_PF1/2(t)` 小幅辅助修正；
- `I_Div(t)=0`，`I_VS(t)=0` 或只给裕度。

这些结果不是凭空写出来的，也不是一开始就需要大型仿真软件才能得到。对于本考核题，最容易实现、最符合 Skill 定位的方法是：

> 用 Python 写一个“规则 + 简化物理公式 + 约束检查”的离线波形生成器。

也就是说，不建议一开始就接入复杂软件；也不建议完全手写死固定答案。最合适的是把物理逻辑封装成可调规则，让 Skill 根据输入目标自动生成一组候选波形。

---

## 2. 这类结果到底怎么从初始数据得到？

以阶段一 Breakdown 为例，输入数据通常包括：

| 初始输入 | 物理含义 | 会影响什么 |
|---|---|---|
| 击穿时间 `t_break = 0–0.05 s` | 需要在很短时间内建立等离子体 | 决定 CS 电流变化速度 |
| 击穿位置 `R=1.85 m, Z=0` | 希望等离子体先在哪里产生 | 决定 PF 零场点计算位置 |
| 背景环向场 `B_t=12 T` | 由 TF 线圈提供约束场 | 通常作为常值背景 |
| 目标初始 loop voltage | 击穿需要的感应电压 | 决定 CS swing 幅度 |
| PF 电流上下限 | 工程限制 | 决定 PF 预置电流不能太大 |

Skill 的任务是把这些输入转成线圈电流时序。传播逻辑可以理解成：

```text
击穿时间 + loop voltage 需求
        ↓
估算 CS 需要多快改变电流
        ↓
生成 I_CS(t) 的快速 swing
```

以及：

```text
击穿位置 R,Z
        ↓
计算该位置由 PF 线圈产生的 B_R、B_Z
        ↓
调节 PF3/PF4 电流，使击穿点附近极向场尽量小
        ↓
得到 PF3/PF4 的预置电流
```

所以 `08工作流.md` 中的输出波形特征，本质上来自两件事：

1. **CS 负责产生感应电压**，因此必须快速变化；
2. **PF 负责创造适合击穿的磁场环境**，因此要在击穿前预置到合适电流。

## 3. 是用软件，还是用 Python 写死公式？

推荐采用“三层实现法”。

### 第一层：规则模板

这是最容易实现的部分，也最适合 Skill。

例如：

- 击穿阶段：CS 快速 swing；PF3/PF4 先预置；Div/VS 不主动参与；
- 爬升阶段：CS 持续变化；PF 跟随 `I_p` 调整平衡；
- 平顶阶段：CS 慢变；PF 近稳态；Div 微调打击点；VS 留反馈裕度。

这部分可以由 Skill 根据阶段直接选择规则，不需要复杂计算。

### 第二层：简化物理公式

这部分用 Python 实现，不是写死固定答案，而是写“可调参数公式”。

例如阶段一可以使用：

```text
I_CS(t) = I_CS_precharge + ΔI_CS · smoothstep(t / t_break)
```

其中：

- `I_CS_precharge` 是预充磁电流；
- `ΔI_CS` 根据所需 loop voltage 或经验比例给出；
- `smoothstep` 用来避免电流突变。

PF 零场可以用一个简化线性模型：

```text
[B_R, B_Z] = response_matrix · [I_PF1, I_PF2, I_PF3, I_PF4]
```

然后求一个最小二乘解：

```text
选择 I_PF，使击穿点附近 B_R ≈ 0, B_Z ≈ 0
```

这样做比完全手写死电流值更好，因为换一个击穿位置或换一个目标时间，Skill 仍然能重新生成波形。

### 第三层：轻量验证

生成初版波形后，不马上上复杂仿真，而是先做简单检查：

- 电流是否超过线圈上限；
- 电流变化率是否过大；
- CS 伏秒是否足够；
- 击穿点附近极向场是否足够低；
- 波形是否连续、平滑、没有不合理跳变。

这些检查都可以用 Python 完成。

## 4. 为什么不优先使用大型仿真软件？

Bluemira、FreeGS、Fiesta、TORAX、EFIT 类工具都可以用于更高级验证，但对本任务的第一版 Skill 来说，它们不是最容易的入口。

原因是：

1. **接入成本高**：需要装依赖、准备机器几何、线圈位置、边界条件；
2. **参数不全**：公开资料不一定给出完整 SPARC 工程细节；
3. **本题不要求最终工程定型**：重点是过程、封装思路和验证逻辑；
4. **Skill 要能稳定运行**：纯 Python 规则生成器更容易复现、展示和迭代。

因此建议：

> 第一版 Skill 用 Python 规则生成器完成；第二版再把 FreeGS / Bluemira 作为可选验证后端。

## 5. 对阶段一的具体实现建议

阶段一可以拆成四个函数。

### 5.1 生成时间网格

输入：

- `t_start = 0`
- `t_end = 0.05`
- `dt = 0.001` 或更小

输出：

- 一个时间数组 `t`

作用：后面所有线圈电流都在这个时间数组上生成。

### 5.2 生成 CS 波形

输入：

- 击穿时间 `t_break`
- 预充磁电流 `I_CS_precharge`
- swing 幅度 `ΔI_CS`
- 最大变化率 `dI_CS/dt limit`

输出：

- `I_CS1(t)`
- `I_CS2(t)`
- `I_CS3(t)`

实现逻辑：

```text
用 smoothstep 或 tanh 生成快速但平滑的电流变化。
```

结果解释：

```text
CS 电流变化 → 磁通变化 → loop voltage → 帮助气体击穿并产生种子等离子体电流。
```

### 5.3 生成 PF 预置电流

输入：

- 击穿点 `R_break, Z_break`
- PF 线圈响应矩阵 `A`
- PF 电流上下限

输出：

- `I_PF1(t)`
- `I_PF2(t)`
- `I_PF3(t)`
- `I_PF4(t)`

实现逻辑：

```text
A · I_PF ≈ [0, 0]
```

也就是让击穿点处的 `B_R` 和 `B_Z` 尽量接近 0。

由于 `A` 在第一版中可以用近似几何公式或经验矩阵代替，所以实现难度不高。第一版甚至可以只让 PF3/PF4 参与主调节，PF1/PF2 给小修正。

### 5.4 生成 Div / VS 基准

阶段一不需要 Div 和 VS 主动参与，因此直接输出：

```text
I_Div1(t) = 0
I_Div2(t) = 0
I_VS(t) = 0
```

或者只记录：

```text
VS_feedback_margin = allowed
```

## 6. Skill 最容易实现的总体架构

建议把 Skill 做成一个离线波形设计助手，内部流程如下：

```text
用户输入目标参数
        ↓
读取 SPARC 简化装置参数
        ↓
按 Breakdown / Ramp-up / Flat-top 分阶段生成目标轨迹
        ↓
用规则和简化公式生成 CS、PF、Div、VS 波形
        ↓
做电流、斜率、伏秒、零场、平衡趋势检查
        ↓
输出 CSV 波形表 + Markdown 解释报告 + 下一轮修正建议
```

推荐输出文件：

| 文件 | 内容 |
|---|---|
| `waveform_candidate.csv` | 时间序列电流波形 |
| `waveform_report.md` | 每阶段逻辑解释、约束检查、风险提示 |
| `config.yaml` | 目标参数和装置简化参数 |
| `plot_waveforms.png` | 线圈电流曲线图 |

## 7. 最小可行版本怎么做？

最小可行版本不需要复杂软件，只需要 Python。

推荐技术栈：

- `numpy`：生成时间序列、矩阵计算；
- `scipy`：最小二乘、平滑插值，可选；
- `pandas`：输出 CSV；
- `matplotlib`：画波形图；
- `pyyaml`：读取配置，可选。

第一版功能：

1. 用户给定 `I_p_flat、t_break、t_ramp、t_flat、R_break、Z_break`；
2. 程序生成 `I_p(t)` 目标轨迹；
3. 程序生成 CS 波形；
4. 程序生成 PF 初版波形；
5. Div / VS 用简化规则给出；
6. 检查线圈电流和变化率；
7. 输出表格和解释报告。

这已经足够体现本题要求的：

- 阶段拆解；
- 波形逻辑设计；
- 参数初选；
- 初步推演；
- 验证逻辑；
- Skill 封装思路。

## 8. 推荐结论

对于本任务，最容易实现、最稳妥、最能体现 Skill 价值的路线是：

> 不从大型仿真软件起步，而是先写一个 Python 离线规则生成器。它不是把电流数值写死，而是把“CS 负责感应电压、PF 负责零场和平衡、Div 负责平顶打击点、VS 负责稳定裕度”这些物理规律封装成可参数化规则。

后续迭代时，再把 FreeGS、Bluemira 或其他 Grad-Shafranov 平衡代码接入为验证后端，而不是第一版核心依赖。

因此，阶段一中从初始数据得到 `I_CS`、`I_PF`、`I_Div`、`I_VS` 的最简实现方式是：

```text
初始数据
  → 阶段规则判断
  → CS smoothstep 波形
  → PF 零场最小二乘预置
  → Div/VS 置零或给裕度
  → 约束检查
  → 输出阶段一波形说明
```

这条路线既简单可实现，又不会显得只是主观猜测，因为每一步都有对应的物理含义和检查指标。
