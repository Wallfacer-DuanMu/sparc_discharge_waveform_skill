# 第三阶段 Flat-top 物理升级改动规划

本文是后续把第三阶段从当前“经验保持 + 平滑修正”的简化模型升级为“最小物理约束维持模型”的实施纲领。重点不只是修改 `stage_3_flattop` 本身，还要保证第二阶段到第三阶段的交接、全局 pipeline 串流、公共适配层、单位和报告输出都能够真正跑通。

与第二阶段改动规划相同，这份文档既关注第三阶段内部升级，也关注全项目链路：

```text
Stage 1 Breakdown
  → Stage 2 Ramp-up
  → Stage 3 Flat-top
  → outputs / reports / validation
```

第三阶段只有放在这条完整链路里，升级才有意义。

---

## 一、当前状态判断

### 1. 已具备的基础

当前工程已经具备：

- `stage_1_breakdown` 的最小物理击穿链路；
- `stage_2_rampup` 的第一版最小物理升级规划文档；
- `stage_3_flattop` 已有完整目录结构：`README.md`、`example.yaml`、`models.py`、`validation.py`、`generate.py`；
- `pipeline/run_pipeline.py` 已具备全流程输出框架；
- `common/state.py` 与 `common/adapters.py` 已经开始承担阶段结果拼接与适配职责；
- 当前 Stage 3 单独运行已经可以输出平顶波形、JSON、CSV 和验证报告。

### 2. 当前第三阶段的问题

虽然第三阶段已经“能跑”，但目前仍主要是经验级维持逻辑：

- `generate_loop_voltage_profile()` 只是把入口电压平滑过渡到目标低电压，没有由等离子体电路方程推导；
- `generate_cs_waveforms()` 仍通过“伏秒积分对应小幅 CS swing”的经验比例生成波形，没有显式使用 CS 互感；
- `generate_pf_waveforms()` 仍是将位形误差乘以人工修正增益后直接修正 `PF1~PF4`；
- `estimate_q95_profile()` 仍是从入口值平滑趋近目标值，并非由 $B_T,R,a,I_p,\kappa,\delta$ 估算；
- 当前 `Div` 打击点扫描和 `VS` 预留范围虽然有结构，但尚未形成明确物理方程链；
- Stage 3 与 Stage 2 的交接字段虽然已有雏形，但尚未以“真实阶段输出 → 真实阶段输入”方式完全闭合。

### 3. 全局串流问题

当前项目的关键风险依旧是：

```text
单阶段能跑 ≠ pipeline 真正使用了该阶段真实模型
```

如果 Pipeline 仍通过占位状态或弱适配逻辑构造 Stage 3 输入，那么即使 `stage_3_flattop/models.py` 升级了，也可能只是“单包更真实”，而不是真正串入全局流程。

因此第三阶段改动规划必须明确两件事：

1. `stage_3_flattop` 内部怎么改；
2. Stage 2 → Stage 3 → Pipeline → 报告 怎么一起改。

---

## 二、总目标

升级完成后，第三阶段应达到：

```text
Stage 2 handoff_to_stage_3
  → Stage 3 Flat-top 最小物理维持模型
  → final_state / validation / diagnostics
  → pipeline 总波形与总报告
```

其中第三阶段核心链路应变成：

```text
Ip_hold(t), shape_hold(t)
  → Lp(t), li(t), Rp(t)
  → V_loop_required(t)
  → CS mutual inductance maintenance
  → flux consumption and remaining margin

Ip_hold(t), shape_hold(t), li(t), beta_p(t)
  → Bv_required(t)
  → PF response matrix solve
  → PF hold corrections and residuals

X-point / strike-point targets
  → PF / Div equivalent response
  → divertor operating point hold
```

最终达到的效果是：第三阶段不再只是“平滑过渡到低电压 + 小幅修修 PF”，而是有一条与 Stage 2 一致的、可解释的物理维持链路。

## 三、建议分阶段实施

### 阶段 A：只做 Stage 3 单包内部物理升级

目标：先让 `python stages/stage_3_flattop/generate.py` 使用更真实的电路、PF、Div 和稳定裕度模型，并输出更完整诊断字段。

特点：

- 风险可控；
- 不依赖 pipeline 先改完；
- 容易快速验证。

### 阶段 B：建立 Stage 2 → Stage 3 标准 handoff 适配层

目标：统一 Stage 2 输出与 Stage 3 输入之间的字段名、单位和结构，避免当前 `example.yaml` 只是手写示例。

重点：

- 真实 `handoff_to_stage_3`；
- 单位转换；
- `physics_diagnostics` 透传。

### 阶段 C：Pipeline 接入真实 Stage 3 计算器

目标：让 `pipeline/run_pipeline.py` 调用 `stage_3_flattop.generate.generate_flattop()`，而不是只在全局状态中构造简化平顶占位结果。

### 阶段 D：升级总报告与输出汇总

目标：让 `process_state.json`、`waveforms.csv`、`validation_report.md`、`stage_summary.md` 真实呈现 Stage 3 物理诊断，而不是只展示少量最终状态。

### 1. `sparc_discharge_waveform_skill/stages/stage_3_flattop/models.py`

这是第三阶段主要改动文件。

建议新增或替换以下内容。

#### 新增常量与默认物理参数

- `MU0`
- `DEFAULT_CS_MUTUAL_INDUCTANCE_H`
- `DEFAULT_PF_RESPONSE_MATRIX`
- `DEFAULT_DIV_RESPONSE_MATRIX`
- `DEFAULT_PF_HOLD_WEIGHTS`
- `DEFAULT_PLATFORM_PHYSICS`

#### 新增等离子体电路函数

建议新增：

- `generate_internal_inductance_profile(times, config)`
- `generate_temperature_profile(times, config)`
- `generate_plasma_resistance_profile(times, config)`
- `compute_plasma_inductance_profile(times, shape_profile, li_profile)`
- `compute_loop_voltage_required(times, ip_profile, lp_profile, rp_profile)`
- `split_loop_voltage_terms(times, ip_profile, lp_profile, rp_profile)`

用途：

- 替代当前 `generate_loop_voltage_profile()` 的纯插值写法；
- 使 Stage 3 平台低环电压与 $L_p,R_p,I_p$ 绑定。

#### 替换 CS 平台维持函数

当前：

```text
generate_cs_waveforms(times, initial_currents_ka, loop_voltage, share)
```

建议升级为：

```text
generate_cs_waveforms_from_mutual_inductance(
    times,
    initial_currents,
    loop_voltage_required,
    mutual_inductance,
    share,
    unit="kA"
)
```

并输出：

- `cs_waveforms`
- `loop_voltage_cs_V`
- `stage_3_flux_used_Wb`
- `cs_slew_rates`
- `cs_maintenance_residual`

#### 新增 PF 平台保持函数

建议新增：

- `compute_poloidal_beta_profile(times, config)`
- `compute_required_vertical_field(ip_profile, shape_profile, li_profile, beta_p_profile)`
- `build_pf_hold_target_vector(...)`
- `get_pf_response_matrix(config)`
- `solve_pf_hold_currents_least_squares(...)`
- `generate_pf_waveforms_from_response_matrix(...)`
- `compute_pf_balance_residuals(...)`

用途：

- 用响应矩阵替代当前 `generate_pf_waveforms()` 内的经验修正公式；
- 把平台目标解释为“平衡 + 位形保持 + X 点保持”。

#### 新增 X 点 / Div 等效控制函数

建议新增：

- `generate_x_point_target_profile(...)`
- `generate_strike_point_target_profile(...)`
- `get_div_response_matrix(config)`
- `solve_div_hold_currents(...)`
- `compute_strike_point_residuals(...)`

如果首版不想让 `Div` 直接进入矩阵求解，也应至少把当前的扫描逻辑和目标点误差计算显式区分开：

- 一个生成目标轨迹；
- 一个生成线圈电流；
- 一个验证误差。

#### 替换 q95 估算

当前：

```text
estimate_q95_profile(times, start_q95, target_q95)
```

建议替换为：

```text
estimate_q95_profile_from_geometry(ip_profile, shape_profile, b0_t, target_q95)
```

使用：

$$
q_{95}\approx C_q\frac{a^2B_T}{RI_p}F(\kappa,\delta)
$$

#### 扩展 `build_waveform_rows()`

建议新增输出字段：

- `plasma_inductance_H`
- `plasma_resistance_ohm`
- `electron_temperature_eV`
- `loop_voltage_required_V`
- `loop_voltage_cs_V`
- `loop_voltage_inductive_V`
- `loop_voltage_resistive_V`
- `stage_3_flux_used_Wb`
- `poloidal_beta`
- `Bv_required_T`
- `pf_balance_residual`
- `x_point_residual`
- `strike_point_residual`
- `vs_reserved_fraction`

### 3. `sparc_discharge_waveform_skill/stages/stage_3_flattop/validation.py`

需要扩展验证项。

建议新增：

- `loop_voltage_physics_available`：是否输出 `loop_voltage_required_V`；
- `cs_mutual_tracking`：`loop_voltage_cs_V` 是否跟踪 `loop_voltage_required_V`；
- `plasma_inductance_range`：$L_p(t)$ 是否为正且合理；
- `plasma_resistance_range`：$R_p(t)$ 是否非负且数量级合理；
- `stage_3_flux_budget`：是否不超过本阶段最大消耗；
- `final_flux_margin`：末端剩余伏秒比例是否满足；
- `pf_balance_residual`：PF 平衡残差是否低于容差；
- `x_point_hold_error`：X 点偏差是否低于容差；
- `strike_point_hold_error`：打击点偏差或扫描幅值是否满足；
- `q95_geometry_based`：q95 是否由几何估算且高于下限；
- `internal_inductance_range`；
- `vertical_stability_margin`；
- `vs_reserve_consistency`：VS 预留范围是否满足要求；
- `final_state_fields_complete`。

旧有检查仍应保留：

- 时间轴单调；
- 平台电流偏差；
- 线圈电流限幅；
- 线圈变化率；
- 位形保持容差；
- Div 扫描约束；
- 结果字段完整性。

## 五、单位统一策略

### 1. 推荐内部标准

建议继续沿用项目的逐步统一策略：

- 时间：`s`
- 等离子体电流：`MA`
- 线圈电流：阶段内部可暂保留 `kA`，pipeline 状态建议逐步统一为 `MA`
- 伏秒/磁通：统一物理量 `Vs/Wb`
- 磁场：`T`
- 电感/互感：`H`
- 电阻：`ohm`

### 2. 第三阶段当前冲突

- `handoff_from_stage_2` 中线圈电流为 `kA`；
- pipeline 总结果可能使用 `MA`；
- Stage 3 `final_state` 使用 `coil_currents_kA`；
- 全局总表 `waveforms.csv` 若使用 `I_CS1_MA`，则必须在适配层转换。

### 3. 短期策略

短期不要为了统一单位而一次性重构所有阶段。

建议：

```text
Stage 2 / Stage 3 单阶段内部：kA
Pipeline 汇总层：显式转换成 MA
```

并在适配函数中明确命名：

- `ka_to_ma`
- `ma_to_ka`

### 4. 长期策略

长期建议三阶段线圈电流统一为 `MA`，但这应放在真实物理链路跑通之后，再做一次独立的“单位统一重构”。

## 六、Pipeline 串流设计

### 1. Stage 2 → Stage 3

升级后 Stage 2 标准输出建议至少包含：

```yaml
stage_2_result:
  Ip_at_rampup_end_MA: ...
  loop_voltage_at_rampup_end_V: ...
  coil_state_at_rampup_end: {...}
  shape_state_at_rampup_end: {...}
  cs_flux_used_rampup_Vs: ...
  cs_flux_remaining_after_rampup_Vs: ...
  q95_end: ...
  internal_inductance_end: ...
  vertical_stability_margin_end: ...
  physics_diagnostics: {...}
  rampup_validation: {...}
```

需要映射到 Stage 3：

```yaml
handoff_from_stage_2:
  time_s: <rampup_end_time>
  plasma_current_MA: <Ip_end>
  loop_voltage_V: <V_loop_end>
  flux_consumed_Wb: <total_used>
  flux_remaining_Wb: <remaining>
  q95: <q95_end>
  internal_inductance: <li_end>
  vertical_stability_margin: <margin_end>
  target_shape: <shape_state_at_rampup_end>
  coil_currents_kA: <converted currents>
  physics_diagnostics: {...}
  constraint_status:
    stage_2_status: valid|failed
```

### 2. Stage 3 → final pipeline result

Stage 3 应向最终总结果传递：

- 完整平台波形；
- 最终线圈状态；
- 最终剩余伏秒与平台消耗；
- 位形与偏滤器工作点；
- VS 预留范围；
- 平台约束检查结果；
- 物理诊断字段。

### 3. Stage 3 失败处理

若 Stage 3 验证失败，Pipeline 应：

- 将 `stage_3_result.flattop_validation.passed=false`；
- 在总报告中明确说明“平台维持不可行”；
- 默认不把失败结果标记为整体成功；
- 如配置允许 `continue_with_warning`，则继续输出，但必须在总摘要中显式警告。

`revision_suggestions.md` 优先建议：

- 缩短平台持续时间；
- 增大 Stage 2 末端剩余伏秒；
- 降低平台目标电流；
- 放宽形状目标；
- 调整 PF hold 权重；
- 调整 Div 扫描幅度；
- 提高 VS 预留。

## 九、主要风险与处理

### 风险 1：平台环电压模型过小或过于理想化

处理：不要把平台环电压直接压成常数或零；至少保留 $R_p I_p$ 项，并在输出中拆分感应项与电阻项。

### 风险 2：互感参数数量级不合适导致 CS 变化率异常

处理：不静默裁剪，直接验证失败并建议调整平台持续时间、互感系数或 `share`。

### 风险 3：PF 响应矩阵病态

处理：采用正则化最小二乘；在诊断中加入 `pf_solver_condition_warning`。

### 风险 4：Div 响应模型过弱，打击点控制沦为“装饰扫描”

处理：即便首版不做完整反演，也要显式输出目标误差和当前等效控制假设。

### 风险 5：Stage 2 handoff 字段不足

处理：先扩展 Stage 2 输出字段，再做 Stage 3 接入，不要让 Stage 3 长期依赖“手写示例入口”。

### 风险 6：单位混用导致平台末态错误

处理：适配层显式写清 `kA ↔ MA`，并在总输出中统一列名。

## 十一、最终建议

本次第三阶段升级不要追求“完整 SPARC 平顶控制仿真”，而要优先实现下面这条最小但真实的物理链路：

```text
平台目标 Ip 和位形
  → 等离子体电路方程
  → CS 互感与伏秒预算
  → Shafranov 型平衡需求
  → PF 平台保持响应矩阵
  → Div 打击点等效控制
  → q95 / li / VS 裕度 / 剩余伏秒检查
  → final_state 与 pipeline 汇总
```

只要这条链路跑通，第三阶段就已经从“平滑持平脚本”升级为当前项目边界内可解释、可检查、可与前两阶段串联的最小物理维持模型；而这也正是后续真正推动全项目从“示例工具”走向“结构完整的离线波形规划器”的关键一步。
