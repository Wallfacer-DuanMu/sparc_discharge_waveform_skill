# 第二阶段 Ramp-up 物理升级改动规划

本文是后续把第二阶段从经验公式升级为最小物理模型的实施纲领。重点不只是修改 `stage_2_rampup`，还要保证全局 Pipeline、公共状态、单位、阶段交接和输出报告都能跑通。

---

## 一、当前状态判断

### 1. 已具备的基础

当前工程已经具备：

- `stage_1_breakdown` 已有较清楚的最小物理模型：真空环电感、等离子体电路、CS 互感、PF 零场系数矩阵；
- `stage_2_rampup` 已有可运行工作包，包含 `example.yaml`、`generate.py`、`models.py`、`validation.py`；
- `stage_3_flattop` 已有自包含工作包；
- `pipeline/run_pipeline.py` 已能生成三阶段最小闭环输出；
- `common/state.py` 已承担当前 pipeline 的占位阶段结果构造。

### 2. 当前第二阶段的问题

`stage_2_rampup/models.py` 当前主要仍是经验模型：

- `generate_loop_voltage_profile()` 使用人为设定的初末电压平滑衰减；
- `generate_cs_waveforms()` 使用“环电压积分每 100 Vs 对应约 10 kA 总 CS swing”的经验比例；
- `generate_pf_waveforms()` 使用若干硬编码比例，例如 `3.0 * (kappa - 1.1)`、`3.5 * current_fraction`；
- `estimate_q95_profile()` 只是从高值平滑接近目标值，没有由 $B_T,R,a,I_p,\kappa,\delta$ 估算；
- 缺少 Ramp-up 物理诊断量，例如 $L_p(t)$、$R_p(t)$、$V_{loop,req}$、$B_v^{req}$、PF 平衡残差等；
- 单独阶段使用 `kA/Wb`，全局 pipeline 使用 `MA/Vs`，需要统一适配。

### 3. 全局串流问题

当前 `pipeline/run_pipeline.py` 仍调用 `common/state.py` 中的 `make_stage_1_result`、`make_stage_2_result`、`make_stage_3_result`，也就是说：

```text
pipeline 当前并没有真正调用 stages/stage_2_rampup/generate.py
```

因此后续如果只改 `stage_2_rampup/models.py`，单阶段可以升级，但全流程仍可能继续使用占位逻辑。必须规划 pipeline 接入和字段适配。

---

## 二、总目标

升级完成后，应达到：

```text
config/input_template.yaml 或阶段 YAML
  → Stage 1 Breakdown 真实最小物理计算
  → 标准 handoff_to_stage_2
  → Stage 2 Ramp-up 真实最小物理计算
  → 标准 handoff_to_stage_3
  → Stage 3 Flat-top 继续运行
  → process_state.json / waveforms.csv / reports 全流程一致输出
```

第二阶段核心替换为：

```text
Ip(t), shape(t)
  → Lp(t), li(t), Rp(t), Te(t)
  → V_loop_required(t)
  → CS mutual inductance integration
  → CS currents + flux consumption

Ip(t), shape(t), li(t), beta_p(t)
  → Bv_required(t), shape target vector
  → PF response matrix solve
  → PF currents + residuals
```

---

## 三、建议分阶段实施

### 阶段 A：只做第二阶段单包升级

目标：让 `python stages/stage_2_rampup/generate.py` 的单阶段运行使用新物理模型，并输出更多诊断量。

特点：风险最小，不影响 pipeline 主流程。

### 阶段 B：建立公共适配层

目标：让 Stage 1 输出能够自动转换成 Stage 2 输入，让 Stage 2 输出能够自动转换成 Stage 3 输入。

重点：单位、字段命名和 handoff 结构统一。

### 阶段 C：Pipeline 接入真实阶段计算器

目标：把 `pipeline/run_pipeline.py` 从 `common/state.py` 占位函数切换到 `stages/stage_*/generate.py` 的真实计算函数。

特点：全流程开始真正使用阶段内部物理模型。

### 阶段 D：公共约束和报告升级

目标：把三阶段重复的限幅、变化率、伏秒、连续性检查逐步抽到 `common/constraints.py`，把报告中的物理诊断量补齐。

这是第二阶段主要改动文件。

建议新增或替换以下函数：

#### 新增常量与默认物理参数

- `MU0`
- `DEFAULT_CS_MUTUAL_INDUCTANCE_H`
- `DEFAULT_PF_RESPONSE_MATRIX`

#### 新增电路模型函数

- `vacuum_loop_inductance_h(device_or_shape)`

- `generate_temperature_profile(times, config)`
- `generate_plasma_resistance_profile(times, config)`
- `compute_plasma_inductance_profile(times, shape_profile, li_profile)`
- `compute_loop_voltage_required(times, ip_profile, lp_profile, rp_profile)`
- `split_loop_voltage_terms(times, ip_profile, lp_profile, rp_profile)`

用途：替代当前 `generate_loop_voltage_profile()` 的人为电压曲线。

#### 替换 CS 波形函数

当前：

```text
generate_cs_waveforms(times, initial_currents_ka, loop_voltage)
```

建议升级为：

```text
generate_cs_waveforms_from_mutual_inductance(
    times,
    initial_currents,
    loop_voltage_required,
    mutual_inductance,
    share,
    unit="kA"
)
```

核心公式：

$$
\frac{dI_{CS_i}}{dt}=-s_i\frac{V_{loop,req}}{M_{eff}}
$$

并输出：

- `cs_waveforms`
- `loop_voltage_cs_V`
- `cs_slew_rates`
- `cs_flux_used_stage_Wb`

#### 新增 PF 物理函数

- `compute_poloidal_beta_profile(times, config)`
- `compute_required_vertical_field(ip_profile, shape_profile, li_profile, beta_p_profile)`
- `build_pf_target_vector(...)`
- `get_pf_response_matrix(config)`
- `solve_pf_currents_least_squares(...)`
- `generate_pf_waveforms_from_response_matrix(...)`
- `compute_pf_balance_residuals(...)`

用途：替代当前 `generate_pf_waveforms()` 中硬编码比例。

#### 替换 q95 估算

当前 `estimate_q95_profile()` 从高值平滑到目标值。

建议替换为：

```text
estimate_q95_profile_from_geometry(ip_profile, shape_profile, b0_t, target_q95)
```

使用：

$$
q_{95}\approx C_q\frac{a^2B_T}{RI_p}F(\kappa,\delta)
$$

其中 $C_q$ 可按末端目标校准。

#### 扩展 `build_waveform_rows()`

新增输出字段：

- `plasma_inductance_H`
- `plasma_resistance_ohm`
- `electron_temperature_eV`
- `loop_voltage_required_V`
- `loop_voltage_cs_V`
- `loop_voltage_inductive_V`
- `loop_voltage_resistive_V`
- `cs_flux_used_stage_Wb`
- `cs_flux_remaining_Wb`
- `poloidal_beta`
- `Bv_required_T`
- `pf_balance_residual`
- `vs_reserved_fraction`

## 五、单位统一策略

### 1. 推荐内部标准

建议全局逐步统一为：

- 时间：`s`
- 等离子体电流：`MA`
- 线圈电流：阶段内部可用 `kA`，但 pipeline 状态建议统一 `MA`
- 伏秒/磁通：统一物理单位为 `Vs`，兼容字段名 `Wb`
- 磁场：`T`
- 电感/互感：`H`
- 电阻：`ohm`

### 2. 当前冲突

- Stage 1 输出线圈电流多为 `MA`；
- Stage 2 示例输入线圈电流为 `kA`；
- Pipeline `waveforms.csv` 列名为 `I_CS1_MA`；
- Stage 2 单阶段输出列名为 `I_CS1_kA`。

### 3. 短期处理

短期不要强行改所有 Stage 2 单阶段文件的单位。建议在适配层显式转换：

```text
Stage 1 MA → Stage 2 kA: value_kA = value_MA * 1000
Stage 2 kA → Pipeline MA: value_MA = value_kA / 1000
```

但报告中必须写清楚单位，避免把 kA 当 MA 串入后续阶段。

### 4. 长期处理

长期建议统一所有阶段线圈电流为 `MA`，并将 Stage 2 的字段名从 `I_CS1_kA` 改成 `I_CS1_MA`。这会影响较多文件，建议放在物理模型跑通之后进行。

## 六、Pipeline 串流设计

### 1. Stage 1 → Stage 2

Stage 1 标准输出：

```yaml
stage_1_result:
  Ip_at_breakdown_end_MA: 0.15
  coil_state_at_breakdown_end:
    CS1: ...
    CS2: ...
    CS3: ...
    PF1: ...
    PF2: ...
    PF3: ...
    PF4: ...
    Div1: ...
    Div2: ...
    VS: ...
  cs_flux_used_breakdown_Vs: ...
  cs_flux_remaining_after_breakdown_Vs: ...
```

需要映射成 Stage 2：

```yaml
handoff_from_stage_1:
  time_s: timeline.breakdown_end_s
  plasma_current_MA: stage_1_result.Ip_at_breakdown_end_MA
  flux_consumed_Wb: stage_1_result.cs_flux_used_breakdown_Vs
  coil_currents_kA:
    CS1: coil_state_at_breakdown_end.CS1 * 1000
    ...
  plasma_state:
    breakdown_success: stage_1_result.breakdown_validation.passed
    major_radius_m: device.R0_m
    minor_radius_m: initial_minor_radius
    elongation: initial_kappa
    triangularity: initial_delta
```

### 2. Stage 2 → Stage 3

Stage 2 标准输出应保留：

```yaml
stage_2_result:
  Ip_at_rampup_end_MA: ...
  coil_state_at_rampup_end: {...}
  shape_state_at_rampup_end: {...}
  cs_flux_used_rampup_Vs: ...
  cs_flux_remaining_after_rampup_Vs: ...
  rampup_validation: {...}
```

同时 `handoff_to_stage_3` 需包含 Stage 3 示例所需字段。如果 Stage 3 仍使用 kA，则继续由适配层转换；如果 Stage 3 已可接受 MA，则统一传 MA。

### 3. 全流程失败处理

如果 Stage 2 验证失败，Pipeline 应：

- 停止或标记 `stage_2_result.rampup_validation.passed=false`；
- 不应把失败 handoff 当成正常输入继续生成 Stage 3，除非配置允许 `continue_with_warning`；
- `revision_suggestions.md` 应优先给出：
  - 延长 ramp-up；
  - 降低 Ip 斜率；
  - 降低目标 $\kappa/\delta$；
  - 调整 CS share；
  - 放宽或修正 PF 响应矩阵系数。

## 九、主要风险与处理

### 风险 1：单位混用导致线圈电流错误

处理：所有适配函数命名中显式写 `ma_to_ka` 或 `ka_to_ma`，报告中写清单位。

### 风险 2：互感参数数量级导致 CS 变化率过大

处理：不要静默 clip；验证失败并建议调整 ramp-up 时长、互感系数或 CS share。

### 风险 3：PF 响应矩阵不可逆或病态

处理：使用正则化最小二乘；若矩阵病态，报告 `pf_solver_condition_warning`。

### 风险 4：新增字段破坏旧配置

处理：为新增 `physics` 字段提供默认值；旧字段暂时保留。

### 风险 5：Pipeline 一次性改动过大

处理：先单阶段升级，再适配层，再 pipeline 接入；保留旧占位模式作为回退。

## 十一、最终建议

本次升级不要直接追求完整 SPARC 工程真实度，而应优先实现“物理链路真实”：

```text
目标 Ip 和位形
  → 等离子体电路方程
  → CS 互感和伏秒
  → Shafranov 型平衡需求
  → PF 响应矩阵
  → q95/li/稳定裕度检查
  → 标准 handoff 串流
```

只要这条链路跑通，第二阶段就已经从原来的数值经验公式升级为当前项目边界内可解释、可验证、可继续增强的最小物理模型。
